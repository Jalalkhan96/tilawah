MASTER PROMPT: OFFLINE QURAN PRONUNCIATION & RECITATION CORRECTION APP

Act as a senior Flutter developer, mobile application architect, Arabic typography specialist, Quranic data engineer, and speech-processing engineer. Build a complete, production-ready Quran Pronunciation & Recitation Correction application for Android and iOS.

1. CORE OBJECTIVE

Develop a fully offline Quran learning application that enables users to read the Holy Quran, listen to authentic recitation, record their own voice, compare their recitation against reference audio, identify supported pronunciation mistakes, and improve their recitation through clear feedback.

Prioritize Quranic text accuracy, authentic audio, Arabic readability, privacy, performance, and a professional Madinah Mushaf-inspired user interface.

2. TECHNOLOGY STACK

- Flutter and Dart for Android and iOS.
- Riverpod for state management.
- Clean Architecture with presentation, domain, data, and service layers.
- SQLite for local storage, bookmarks, settings, and practice history.
- Local audio playback and microphone recording.
- Python 3.11 for offline data preparation, audio preprocessing, and alignment-engine evaluation.
- FFmpeg for audio conversion and preprocessing.
- Native libraries or on-device inference for production audio analysis.
- Docker for optional development and data-processing environments.

The installed application must not require a Python server, Docker container, cloud API, or internet connection to perform its core functions.

3. QURANIC TEXT INTEGRATION

Integrate a complete, verified Uthmani Quran dataset, such as quran-uthmani.xml, subject to authenticity and licensing verification.

Include all 114 Surahs and verified Ayah ordering, Arabic text, tashkeel, shaddah, sukun, Quranic symbols, and other meaningful diacritics.

Support Surah, Ayah, word, line, half-line, Ruku, Para/Juz, Hizb, and Mushaf page navigation where reliable metadata is available.

Preserve the original Quranic text exactly. Maintain separate display and analysis representations. Never use an LLM to generate or reconstruct canonical Quranic text. Do not invent page mappings, word boundaries, timestamps, or Quranic annotations.

4. OFFLINE QURAN AUDIO

Provide locally stored, licensed Quran recitation audio with a validated asset manifest.

Implement:
- Play, pause, resume, and stop.
- Verse-by-verse playback.
- Word-level replay when verified timestamps exist.
- Adjustable playback speed.
- Repeat word, Ayah, passage, or selected practice section.
- Automatic next-Ayah playback.
- Seamless audio transitions.
- Audio progress indicators.
- Recovery from interruptions and audio decoding failures.

Store audio files on disk rather than in SQLite. Maintain metadata for Surah, Ayah, duration, format, reciter, file path, and integrity checksum.

The complete Quran audio collection must remain available offline after the assets have been installed.

5. VOICE RECORDING

Allow users to record their recitation directly inside the app.

Workflow:
1. Select a Quranic passage.
2. Listen to the reference recitation.
3. Record the user's recitation.
4. Check recording quality.
5. Analyze and align the recording locally.
6. Display detected differences and confidence information.
7. Replay both recordings.
8. Repeat the exercise.
9. Save practice history locally.

Detect silence, background noise, clipping, incomplete recordings, and unsuitable audio quality. Request a new recording when reliable analysis is not possible.

Recordings must remain on the device and be deletable by the user.

6. PRONUNCIATION CORRECTION ENGINE

Implement a genuine offline audio-alignment and acoustic-comparison pipeline.

Do not use ordinary speech-to-text transcription as the sole method of assessing Quranic pronunciation. General Arabic speech recognition may omit diacritics, normalize words, or fail to distinguish important recitation differences.

The analysis engine should support, where validated:
- Missing or omitted words.
- Extra words or sounds.
- Word substitutions.
- Supported consonant and vowel mismatches.
- Significant timing differences.
- Incomplete recitation.
- Passage alignment failures.
- Grossly shortened or prolonged vowel duration where reliable reference timing is available.

Use reference audio, forced alignment, voice activity detection, acoustic features, and a suitable on-device model where appropriate.

Associate each detected issue with its relevant word or passage. Include confidence thresholds, engine-version metadata, and explicit handling of inconclusive results.

Do not claim that forced alignment alone can detect every tajweed rule or makhraj error. Implement advanced tajweed assessment only when a suitable, validated rule-aware engine is available.

Never fabricate errors, use hard-coded analysis results, or mark uncertain recitation as incorrect.

7. VISUAL FEEDBACK

Use the following feedback system:
- Green: Correctly aligned within validated criteria.
- Yellow: Possible issue or timing discrepancy requiring review.
- Red: Supported error detected with sufficient confidence.
- Gray: Not assessed, low confidence, or insufficient audio quality.

When the user taps a highlighted word, show the word in context, play its reference audio where timestamps permit, replay the corresponding user recording, and explain the detected issue in simple language.

Display uncertainty honestly. Never present an automated score as a definitive religious judgment.

9. UI/UX DESIGN

Create a premium, calm, respectful interface inspired by the Madinah Mushaf.

Use elegant Arabic typography, generous spacing, restrained colors, subtle dividers, accessible controls, and smooth transitions. Avoid flashy gradients, excessive animations, crowded layouts, and distracting gamification.

Arabic rendering must support proper RTL layout, glyph shaping, and Quranic diacritics. Prevent clipped marks, overlapping text, broken words, incorrect punctuation positioning, and layout shifts during navigation.

Support different screen sizes and accessibility settings. Never use fixed-height Arabic text containers that clip Quranic characters.
